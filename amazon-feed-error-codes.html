先用错误码判断问题类型

错误码不是最终答案，但能决定排查顺序。更准确的做法是把 error-code、error-message、attribute-name 和 SKU 放在一起看。

错误码分组后怎么处理

  1. 阻断类先修。8541、8560、8036、99010、90244 常会阻断 SKU 创建、ASIN 匹配或变体关系。
  2. 字段类批量修。8058、90112、90244 往往能按 attribute-name 批量定位，不要逐个 SKU 手改。
  3. 依赖顺序单独看。8008、13013 可能和 SKU 是否已创建、父子体上传顺序或目录状态有关。
  4. 资源类最后复测。20000 这类图片/媒体 URL 问题需要确认 URL 公网可访问、HTTPS 和服务器响应。

来源与边界

部分错误码有 Amazon Seller Central 官方帮助页；部分错误仍需要结合 Processing Report 的 message、attribute-name、站点、类目和账号权限确认。本页是 independent helper，不是 Amazon 官方错误码库。

具体问题先按字段定位

如果同一个错误码下面出现不同字段，例如 90244 unit_count、90244 color_name 或 8058 size_name，不要只按错误码修。先看 Processing Report 的 attribute-name，再回到 flat file 对应列检查 valid value、必填值和 variation theme。

错误码分组后的处理原则

错误码总览页适合先做 triage：目录冲突类错误优先核对 ASIN 和品牌属性；缺字段类错误优先回到模板 Data Definitions；变体类错误优先检查 parent/child 行和 variation theme；媒体类错误则优先确认 URL 是否可被 Amazon 抓取。

同一次上传可能出现多个错误码。处理顺序建议先修阻断 SKU 创建的 8560、99010，再修父子体关系和目录冲突，最后处理图片、卖点或描述类字段。
