Error 13013

Amazon 13013 错误：SKU 不在目录中或已被删除

13013 不是图片链接错误。它通常表示这条记录引用的 SKU 或商品无法作为当前目录商品处理：SKU 可能尚未成功创建、已被删除、跨站点本地化未完成，或 product-id / ASIN / SKU 关系不一致。

Updated: 2026-06-07 - Independent seller utility, not affiliated with Amazon.

优先检查字段

sku、external_product_id、product-id、product-id-type、update_delete。

修复步骤

  1. 在 Manage Inventory 中搜索该 SKU，确认它是否存在、是否被删除、是否属于当前 marketplace。
  2. 如果你是在更新已有 SKU，确认 update_delete 不是在更新一个不存在或已删除的 SKU。
  3. 如果你是在创建新 listing，检查 product-id、product-id-type、brand、item_name 等建品字段是否足以创建商品。
  4. 跨 marketplace 复制商品时，等待商品本地化完成后再重新上传。

不要把 13013 误判成什么？

13013 的关键不是先改图片、标题或 bullet，而是确认这条记录引用的 SKU 是否能在当前站点和当前目录上下文中被 Amazon 识别。若同一个 SKU 在其它 marketplace 已存在，也仍可能因为本地站点没有成功创建、被删除、或 product-id 与 ASIN 关系不一致而失败。

复核前准备

  • 保留 Processing Report 中的 sku、original-record-number 和完整错误信息。
  • 在原始 Flat File 中确认 product-id、product-id-type、update_delete 和 SKU 行是否一致。
  • 如果是变体文件，先确认父体与子体是否都已在同一站点成功创建。

程序化页面唯一诊断：13013 不是“缺字段”错误

13013 页面不应只复用通用错误码模板。这个错误更像字段格式和允许值校验失败：同一列可能有值，但值的类型、枚举、长度或大小写不符合当前分类模板。复核时要先比较 Processing Report 的 attribute-name 和模板 Data Definitions，不要直接补空值。若字段看起来已经填写，应重点检查前后空格、中文标点、不可见字符、单位列和值列拆分，以及是否从旧 marketplace 模板复制了枚举。

  • 把失败字段复制到纯文本编辑器，确认没有隐藏换行或全角符号。
  • 优先用模板允许值替换，而不是自己翻译或改写枚举。
  • 若同一 SKU 同时报 8058，应先按 8058 的 allowed value 方向处理。
