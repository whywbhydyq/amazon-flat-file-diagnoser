Amazon Listing 上传错误排查

Listing 批量上传失败时，最重要的是把错误拆成编码问题、目录冲突、缺字段、变体问题和格式问题，而不是混在一起改。先用 Processing Report 定位 row、SKU、attribute-name 和 error-code，再决定哪些能在 flat file 里修，哪些要进入 catalog review 或 Seller Support case。

Updated: 2026-06-06 - Independent seller utility, not affiliated with Amazon.

常见错误类型

  • ASIN 目录冲突：8541；变体关系创建受限：8036。
  • 缺必填字段：99010、8560。
  • 变体关系错误：90244。
  • 子 SKU 引用错误：8008；字段值或日期/数值格式错误：90112；图片/媒体 URL 错误：20000；SKU/catalog 状态错误：13013。

先把失败拆成五类

不要直接重传整份模板。先打开 Processing Report，确认每条错误的 SKU、row number、attribute-name、error-code 和 message。对于同一个 SKU，如果同时出现 8541、99010 和 90244，应先处理 catalog identity 或 variation 关系，再补字段；否则你可能会反复修补一个最终仍无法创建的 listing。

  • Catalog identity / ASIN conflict：通常涉及品牌、UPC/EAN、manufacturer、part number 或已有 ASIN。文件修正只能解决明显字段错误；目录归属冲突通常需要证据和人工 review。
  • Required attribute missing：99010、8560 一类错误要回到最新类目模板，确认必填字段、推荐字段和 theme 触发字段，而不是只补 Processing Report 点名的一个字段。
  • Variation relationship：90244、8036、8008 等错误需要同时检查 parent_sku、parentage、relationship_type、variation_theme 和子体差异属性。
  • Value / format validation：8058、90112 常见于枚举值、日期、数字、单位、URL、大小写或 marketplace 特定值。
  • Media and image URL：20000 类错误要确认 HTTPS、公开访问、重定向、图片尺寸、文件格式和主图字段映射。

什么时候应该小样本重传？

如果错误集中在一两个字段，可以先复制 3 到 10 个代表性 SKU 做小样本上传，验证模板字段和值是否被接受。对于父子体关系，样本必须包含一个 parent 和该 parent 下的多个 child，否则无法确认 variation theme、relationship_type 和 child attribute 的组合是否真的成立。

如果 Processing Report 仍然返回同一个 catalog conflict 或 variation restriction，不要继续大批量重传。此时应整理 SKU、ASIN、品牌、UPC/EAN、错误码、上传批次和你已经尝试的模板字段，作为 Seller Support 或内部 catalog team 的 case brief。

建议流程

  1. 先解析 Processing Report。
  2. 按错误码分组。
  3. 先修阻断错误，再修内容质量错误。
  4. 每次只改一类问题，重新上传小样本验证。

把 Listing 上传错误拆成可执行队列

Listing 上传失败通常不是“文件坏了”，而是多个问题叠加。先按错误类型拆成创建 SKU、目录冲突、必填字段、变体关系和媒体抓取五类；每一类只选少量代表 SKU 复核，避免同时修改过多字段导致无法判断哪一步有效。

如果 Processing Report 没有明确字段名，应优先查看错误信息和原始记录号，再回到当前模板确认该行所属商品类型。不要只凭错误码修改整列。
